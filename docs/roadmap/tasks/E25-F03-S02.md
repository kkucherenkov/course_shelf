## Goal

A pass over a library's videos, modelled on the scan: `202`, work continues after the response, per-lesson failures recorded without failing the run.

## Acceptance

- Refuses to start when no model is configured, and when a run is already active for the library
- Persists `running` and returns it; the walk begins after the response flushes
- Per lesson: skip rule, audio extraction, transcription, cue parsing, one transaction for `Transcript` + `TranscriptCue`
- Temporary `.wav` removed on both the success and the failure path
- Cancellation checked between lessons; the in-flight child is allowed to finish
- Progress published to Centrifugo once per finished lesson
- `extractCues(vtt)` lands beside `convertSrtToVtt`, pure, with its own tests

## Notes

- An `-l auto` run records the language as `und` — whisper detects but returns nothing to read the detection back from, and the same convention already covers a sidecar with no language suffix.
- The walk is sequential by design. A second concurrent whisper process on a NAS competes for the same cores rather than finishing sooner.
- `TranscriptionNotConfiguredError` moved from 422 to **503**. The contract E25-F03-S01 landed documents 503 for an unusable engine and no 422 at all, and `express-openapi-validator` turns an undocumented status into a 400 outside production. The contract won; no spec edit was needed.
- `convertSrtToVtt` moved from `streaming/domain/` to `src/shared/` so `extractCues` could land beside it and still be reachable from the catalog context — `boundaries/element-types` forbids one bounded context importing another.
- The skip rule compares the video's `(mtime, size)` as recorded on the `Lesson` row rather than stat'ing the file: the lesson row is the catalog's record of the file, refreshed by the scan that also refreshes everything else about it.
- Progress rides the existing `scans:user:{userId}` channel with `transcription-*` kinds — no new channel, because a new one would need both an AsyncAPI entry and a `channels` claim in the realtime token, and the card's spec diff is none. The AsyncAPI message variants are still undocumented; see the follow-up task.
- `GET /api/v1/admin/transcriptions` (cross-library admin table) is **not** implemented here. It belongs to the `admin` module's dashboard port rather than the catalog context, and this card's Acceptance does not name it.
