## Goal

Give CourseShelf somewhere legal to write what it generates. `COURSES_PATH` is mounted `:ro` in both production composes, so transcripts and thumbnails need a separate writable volume, and whisper.cpp needs to exist inside the backend image.

## Acceptance

- `AppConfig.derivedPath` (env `DERIVED_PATH`, default `/data/derived`)
- `AppConfig.transcription` — `whisperPath`, `modelPath`, `timeoutMs` (default 6h), `threads`, `language`, and `configured` (false until a model path is set)
- `/data/derived` mounted **writable** in `compose.yml`, `compose.prod.yml`, `compose.release.yml`; `COURSES_PATH` stays `:ro`
- The ggml model is a **mounted read-only file**, never baked into the image
- Backend image carries a pinned whisper.cpp binary; `ffmpeg -version` and `whisper-cli --help` both work inside the container

## Notes

- The 30-second `execFile` timeout that is right for `ffprobe` is wrong by three orders of magnitude for transcription; `WHISPER_TIMEOUT_MS` defaults to six hours.
- Deviation from the plan: the ggml model is bound through a **read-only `/models` directory** (`WHISPER_MODEL_DIR`, created by docker if absent) with `WHISPER_MODEL_PATH` naming the file inside it, rather than the plan's required single-file mount. A required mount would break every existing prod stack on upgrade for operators who do not want transcription; an empty `WHISPER_MODEL_PATH` keeps `configured: false`, which is the fail-fast the card asks for. `DERIVED_PATH` **is** required in prod and release.
- whisper.cpp is pinned through a `WHISPER_CPP_VERSION` build arg (`v1.9.3`) and built in a dedicated stage in both `apps/backend/Dockerfile` and `Dockerfile.dev`, so dev and prod run the same binary. `libgomp` is its one extra runtime package (`ldd whisper-cli` → libgomp, libstdc++, libgcc_s, musl).
- Verified in-container against the dev image: `ffmpeg 8.1.2`, `ffprobe 8.1.2` and `whisper-cli --help` all print.
