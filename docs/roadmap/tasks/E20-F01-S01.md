## Notes

- Completed: 2026-08-29
- Result: https://github.com/kkucherenkov/course_shelf/pull/201

**Scope grew, deliberately.** Two of the three outboxes had no producer:
`notes_outbox` and `bookmarks_outbox` were written by nothing, because the
player called Dio directly and swallowed the error when offline. Draining
tables that never fill would have shipped two thirds of this card as test-only
code, so the player's note and bookmark writes moved onto the outbox too
(`OutboxLessonPlayerRepository`). Only that makes "offline notes and bookmarks"
true rather than notional.

**Deviation.** Acceptance says a conflict "results in client overwrite from
server". There is no local progress cache to overwrite — no Drift table stores
progress, only the outbox. `accepted`, `stale` and `forbidden` are therefore
all terminal for the queued row; what distinguishes `stale` is that it carries
the server's `LessonProgressDto`, which the drain surfaces on `SyncOutcome`
rather than writing somewhere nothing reads. Reconciled with the endpoint's
actual `BatchProgressItemStale` semantics, as this card's own note asked.

**Not delivered.** The `integration_test` under Tests: no emulator on the dev
host and none in CI — the constraint E19-F01-S01 and E19-F01-S03 already
recorded. 40 unit and bloc tests cover every drain rule and every trigger.

**Found and fixed on the way.** `lesson_player_api.dart` and
`http_lesson_byte_source.dart` still doubled the `/api/v1` prefix — the bug
issue #172 fixed in `auth_api.dart` in July and nowhere else. The player's
notes, bookmarks, outline and material downloads were non-functional against a
real backend, as was the byte source behind the download queue.

Backed by `/progress/batch` (the "sync endpoint for offline-first clients") + notes/bookmarks endpoints for the outboxes. Reconcile the conflict-rule wording with the batch endpoint's actual stale-detection (`BatchProgressItemStale`) so they don't drift. `connectivity_plus: ^7.3.1` is already in `apps/mobile/pubspec.yaml` (added with the E19 download queue) — no dependency step needed.
