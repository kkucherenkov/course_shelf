## Goal

Transcribe the one course you are about to watch, instead of the whole library.

## Why

Measured on the maintainer's live instance mid-run, 2026-09-14:

```
startedAt          | 2026-09-13 23:15:48
lessonsTotal       | 5464
lessonsTranscribed | 40          ← after thirteen hours
```

That is **19.5 minutes per lesson**. Of 5464 lessons 1792 have sidecar
subtitles and skip, leaving 3672 to actually run: about **forty-nine days** of
continuous CPU. The host is an Intel Pentium Gold 8505 and `whisper-cli`
already runs at 362 % CPU with `-t 4` of 6 cores on the `base` model — the
hardware's ceiling, not a misconfiguration.

A library-wide run is therefore unusable in practice. Thirty lessons is ten
hours, which is an overnight job; that is the only shape that works.

## The decision

A scoped run is **still blocked** by the library-wide already-running guard.
Whisper saturates every core it is given, so two concurrent runs halve each
other — there is no throughput to win by relaxing it, and a silent
auto-cancel of the operator's library-wide run would be a worse surprise than
a refusal. What changed instead is the message: the 409 now names the run in
flight and the exact cancel call, because the operator hitting it is usually
trying to escape a library-wide run they regret starting, and a bare
"already running" tells them nothing (the same failure #469 cleaned up on the
library form).

## Acceptance

- `POST /api/v1/courses/{id}/transcription` — admin-only, 202 like the
  library-wide run
- `RunTranscriptionCommand` carries an optional scope; the library-wide path
  is unchanged and still the default
- A scoped run walks only that course's lessons and never a sibling's
- The skip rule is unchanged inside a scope: sidecar → skip, unchanged video
  with a current transcript → skip
- The record and all three realtime events carry `scopeCourseId` /
  `scopeCourseName`, so the UI can say "transcribing <course>"
- A Transcribe button on the course page, next to Rescan, admin-only
- Strings via `t()` in `en` and `ru`; `pnpm check:i18n` green

## Tests

Handler: a scoped run transcribes only its own course's lessons (the test that
matters); the skip rule still applies inside a scope and counts a sidecar as
skipped; the scope is named on the record and on every lifecycle event; the
already-running guard refuses a scoped run and its detail names the cancel
route. Adapter: a per-request language reaches whisper's `-l`. HTTP: 202 with
the scope, 404 for an unknown course, 409 naming the run to cancel. Web: the
button is admin-only, calls the route, and shows the server's own `detail` on
failure.

## Notes

- `RunTranscriptionCommand.libraryId` became `string | undefined` with a new
  optional `scope: { courseId }`, exactly as `RunScanCommand` did — same class,
  no discriminated union, every existing call site unchanged.
- Scoping was a two-line change to `loadLessons`: the transcription walk reads
  its lessons through `lessonRepo.findByCourse`, so a scope is one query
  instead of one per course. There is no on-disk folder to resolve and no
  orphan cleanup to make scope-aware — the trap that made the scoped *rescan*
  substantial (E32-F01-S02) simply does not exist here.
- `WHISPER_LANGUAGE=auto` makes whisper run a language-detection pass per file
  and gives nothing to read the result back from, so the transcript is filed
  under `und`. `StartTranscriptionRequest.language` overrides the deployment
  default for one run: it skips the detection pass and files the transcript
  under the real tag. A transcript is identified by `(lesson, language)`, so
  naming a language different from what is already on disk transcribes rather
  than skips — deliberate.
- Deliberate non-goal: no priority queue and no per-course language setting.
  Scope removes the ordering problem for the scoped path, and a request field
  is enough for the language.
