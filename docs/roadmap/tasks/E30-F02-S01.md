## Goal

Fill a Coursera course's metadata from the platform's own catalogue instead of
its HTML.

## Why this is not a declarative definition

Measured 2026-09-13. Coursera answers a **keyless, public JSON API**, so there
is no HTML to select against and the E30-F01 rule vocabulary does not apply.
Three calls, all 200 without credentials:

```
GET api.coursera.org/api/courses.v1?q=slug&slug=<slug>
    &fields=name,description,photoUrl,primaryLanguages,startDate,workload,instructorIds,partnerIds
GET api.coursera.org/api/instructors.v1?ids=<ids>&fields=fullName   → "Andrew Ng"
GET api.coursera.org/api/partners.v1?ids=<id>&fields=name           → "DeepLearning.AI"
```

Course URLs are `coursera.org/learn/<slug>`, so `canHandle` and the slug both
come off the URL — the same shape `UdemyScraper` already uses.

## Acceptance

- `CourseraScraper implements Scraper`, `id: 'coursera'`, registered in
  `build-scraper-registry.ts` among the built-ins (before declarative
  definitions and the `json-ld` fallback)
- `canHandle` matches `coursera.org/learn/<slug>` and nothing else
- `kind: 'url'` fills, from the measurements above: `title` ← `name`,
  `description`, `posterUrl` ← `photoUrl`, `language` ← `primaryLanguages[0]`,
  `releaseDate` ← `startDate` (epoch ms → ISO date), `instructorNames`,
  `studioName` ← first partner, `externalIds` ← `{ source: 'coursera',
  externalId: <course id>, url }` — 8 of the 12 fragment fields
- The two lookup calls are **batched** (`ids=` takes a comma-separated list) and
  skipped entirely when the course carries no ids — never one request per
  instructor
- A failing or slow lookup degrades to a fragment without those names rather
  than failing the whole scrape; the course call failing is a real error
- No API key, and no new dependency — `HttpFetcher` already does the network
