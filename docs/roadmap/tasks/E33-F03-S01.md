## Spec / Design references

- [ADR-0013](../../adr/0013-ownership-taxonomy-and-ratings.md) — decision 4: a
  generated transcript is not a material

## Goal

Answer "is this course transcribed" on the course page, per lesson and across
the whole thing.

## Acceptance

- A transcript section on the course page, separate from the material list
- Coverage across the course — how many lessons of how many have a transcript
- Per-lesson state, from the `hasTranscript` flag `LessonOutlineItem` already
  carries
- Download per lesson, through the existing `streamLessonSubtitle` route
- Strings via `t()` in `en` and `ru`; `pnpm check:i18n` green

## Spec diff

openapi.yaml — a course-wide coverage figure on the course detail response.
Per-lesson state needs nothing: `LessonOutlineItem.hasTranscript` exists and
is already rendered by `CourseSectionsList.vue`, and the download route
exists too. Coverage is the only thing missing.

## Tests

A query spec for coverage, including a course with zero lessons. Component

## Notes

- Opened from `tuxedo` 218.
- A transcript is **not** a `MaterialKind` — the enum stays
  `doc | note | image | slide`. A material is a file that shipped with the
  course; a transcript is produced here, carries a status and a coverage
  figure, can be regenerated and exists per language. Keeping it out of the
  material list is what stops `Material` rows having to be kept in step with
  `Subtitle` and `Transcript` rows on every run.
