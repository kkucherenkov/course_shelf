## Notes

The audit found the spec diff was **not** optional. `GET /api/v1/courses`
already accepted `libraryId`, `status` and a three-value `sort`; it had no
duration or instructor parameter, and `CourseDto` carries no runtime at all —
so filtering client-side over the full list was not possible even in principle.
The contract gained `durationBucket`, `instructorId` and `sort=duration`.

Total runtime comes from the existing `getLessonStatsByCourseIds` groupBy, and
is fetched only when a duration filter or sort is actually asked for, so the
common Browse request keeps its previous query count.
