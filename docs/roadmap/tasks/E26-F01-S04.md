## Goal

A link to a moment should land on that moment. This is also what the later transcript search links to.

## Acceptance

- `parseStartTime(raw)` handles integers, fractions, zero, a repeated query parameter, and rejects negatives, non-numerics, empty and absent values
- An explicit `?t=` wins over the resume position **and** over the “Resume where I left off” preference
- Without `?t=`, resume behaviour is unchanged

## Notes

- `?t=` is read once, on `loadedmetadata`, and beats both the stored resume
  position and the "Resume where I left off" preference. Junk (`?t=abc`,
  `?t=-1`) parses to `null` and leaves resume behaviour untouched.
- **Manual verification done** on an isolated `cs-verify` docker stack (real
  Chromium via Playwright, not the E2E data-URI stub) against a real
  fixture course with an actual `.mp4` and real `.srt` subtitles
  (`docs/data/fixture-course/`, gitignored). `?t=90` landed the player at
  exactly `currentTime=90`. Same pass also confirmed the two other
  never-browser-checked #302 fixes: the subtitle cue never overlaps the
  chrome control bar in windowed **or** fullscreen mode (`CUE_LINE_ABOVE_CHROME
  = -4` needed no adjustment), and a non-16:9 source letterboxes inside the
  16:9 frame instead of overflowing it. See PR for browse/backups (#307)
  verification and screenshots.
