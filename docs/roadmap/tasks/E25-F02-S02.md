## Goal

The run's lifecycle and counters, shaped like `Scan` — status transitions, per-item errors that do not fail the run.

## Acceptance

- `start` / `reconstitute`; `recordSkipped`, `recordTranscribed`, `recordFailure`; `complete`, `fail`, `cancel`
- Counters: total, skipped, transcribed, failed
- Every mutator throws `TranscriptionInTerminalStateError` once the run is closed
- Plain class — no Prisma, no NestJS types

## Notes

- Completed: 2026-08-30
- Result: https://github.com/kkucherenkov/course_shelf/pull/293
- `TranscriptionInTerminalStateError` is a 409, not the 422 `ScanInTerminalStateError`
  uses. The only request handler that can reach it is `POST /transcriptions/{id}/cancel`,
  whose contract documents 409 for "already terminal"; inside the walk it is a bug
  guard whose status never surfaces.
- `transcription.errors.ts` was created here with only the two errors this lane
  needed. E25-F01-S02 and E25-F01-S04 add theirs on top.
- Counters differ from `Scan`'s deliberately: the interesting question is how many lessons were skipped, finished and failed — a resumed run is mostly skips, and that has to be legible in the UI.
