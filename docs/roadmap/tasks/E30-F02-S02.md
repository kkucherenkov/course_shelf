## Goal

Fill a Stepik course's metadata from the platform's own catalogue instead of
its HTML.

## Why this is not a declarative definition

Measured 2026-09-14 against course 181875. Stepik answers a **keyless, public
JSON API** returning 140 fields; three calls, all 200 without credentials:

```
GET stepik.org/api/courses/181875                  → title, summary, description,
                                                      cover, language, instructors[],
                                                      review_summary, create_date,
                                                      acquired_skills[], target_audience,
                                                      requirements, workload
GET stepik.org/api/users?ids[]=564134108           → "Алексей Андросов"
GET stepik.org/api/course-review-summaries/181344  → average 4.95, count 62
```

Without an adapter a Stepik URL falls through to the generic json-ld path and
recovers **one** field, because the page types itself as schema.org `Product`,
which `JsonLdScraper` rejects.

## Why the description is composed

Stepik splits what reads as one description across five fields — `summary`
(plain lead), `description` (HTML body), `acquired_skills[]`,
`target_audience`, `requirements`, `workload`. The model has one
`description`, so they are folded into it under plain-text headings.

Two consequences, both deliberate:

- The headings follow the **course's** language, not the viewer's. They are
  stored, not rendered, so an `en` course must not grow Russian headings
  because the maintainer's UI is Russian. `ru` and `en`, English otherwise.
- The result is capped at **8000** — the wire limit raised in #527 — so a later
  `PATCH /courses/{id}` cannot answer 400. Course 181875 composes to 4734
  characters, measured end to end against the live API.

`description` and `requirements` arrive as HTML. Converted with cheerio —
already a dependency of this directory (`html-metadata.extractor.ts`), so no
new one. The first cut stripped tags with a regular expression and CodeQL
rejected it as `js/incomplete-multi-character-sanitization` (high), correctly:
`<[^>]+>` removes an inner `<script>` and rejoins the surrounding halves into a
live tag, and "this output is never rendered as markup" is a guarantee that has
to hold for every future caller, not just today's. A parser has no such seam,
removes `script`/`style` with their payloads, and decodes entities properly
instead of against a hand-written table. Measured against the live API: the
composed description is byte-identical either way — the behaviour did not
change, the vulnerability class went away.

## Why sections are not imported

The API returns the course's section list. It is deliberately ignored. A course
outline is a fact about **what is on disk**, built by the scan from folders and
files. Taking it from the site would create a second source of truth about the
user's own library, and the two diverge on the first partially downloaded
course.

## Acceptance

- `StepikScraper implements Scraper`, `id: 'stepik'`, registered in
  `build-scraper-registry.ts` among the built-ins, unconditionally — no key, no
  config, like Coursera
- `canHandle` matches `stepik.org/course/<numeric id>` and nothing else — a
  slug in the id position is rejected, because the API takes a number
- `kind: 'url'` fills `title`, `description` (composed), `posterUrl` ← `cover`,
  `language`, `releaseDate` ← `create_date`, `instructorNames`,
  `ratingAverage` / `ratingCount` ← the review summary, and `externalIds` ←
  `{ source: 'stepik', externalId: <course id>, url }` — **9 of the 12**
  fragment fields
- The instructor lookup is **batched** into one `ids[]=` call, and both lookups
  are skipped entirely when the course carries no ids
- A failing or slow lookup degrades to a fragment without those fields; only
  the course call failing is a real error
- No API key, and no new dependency — `HttpFetcher` already does the network

## Tests

Adapter unit tests against recorded fixtures (no live network in CI): the happy
path over all nine fields; the five-field description composition; English
headings for a non-Russian course; the summary not repeated when the body
already opens with it; the 8000 cap; the batched instructor call; both lookups
skipped when there are no ids; a lookup failing; the course call failing;
`canHandle` rejections; and the regex-stripper bypass
(`<<script>script>…`), which pins that a payload never survives — deliberately
without asserting the absence of `<`, since after parsing a stray `<` is a text
node and a course about SQL or HTML legitimately has `WHERE x < 5` in its
prose.

Additionally verified once against the **live** API during development
(a throwaway spec, not committed): 9 fields filled, 4734-character
description, no HTML left in the output.
