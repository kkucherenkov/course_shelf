## Notes

- Completed: 2026-08-29
- Result: https://github.com/kkucherenkov/course_shelf/pull/197

**Deviation — a table and a link, not thumbnails.** The acceptance line says
"PR comment with diff thumbnails". GitHub markdown cannot embed an image from a
workflow artifact, and it strips `data:` URIs, so genuine inline thumbnails
require the PNGs to sit at a public URL. The only in-repo way to get one is to
commit the diffs to a branch and reference `raw.githubusercontent`, which buys
inline images at the price of permanent junk commits and `contents: write` on a
workflow that forks can trigger. Chosen instead: an artifact plus a comment
listing each drifted story with its diff percentage and a link to the run. The
decision was put to the user before implementing.

**Deviation — "required" is not yet true.** `main` has **no branch protection**
(`branches/main/protection` → 404), so no check is required on any PR. The gate
logic is correct the moment protection is enabled — until then it is a red X a
human can choose to ignore. That is a repository settings change rather than a
code change, tracked separately.

**Why `continue-on-error` on the test-runner step is not a masked failure.** The
Verdict step re-raises it, and distinguishes the two failure modes: drift with
entries in the report is gated on the label; a failure with an *empty* report is
a broken Storybook build or a crashed runner and fails unconditionally, because
a label must not wave that past. That distinction is the reason the report file
exists rather than just reading the step's outcome.
