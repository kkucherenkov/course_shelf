## Dependencies

- E32-F01-S01 (position rule) — this card reuses `assignLessonPositions`
  unchanged; only which section a lesson lands in changes.

## Goal

Import a course whose videos live two folders deep as one section per real
subfolder, in the author's order, instead of one section holding every lesson
interleaved.

## The measurement that opened this

Counted on `pre-1.8.0-nas.dump` — the production dump pulled from the NAS on
2026-09-17 — by joining `lesson.videoPath` against `section`, 2026-09-21:

| | |
| --- | --- |
| Lessons on the library | 5973 |
| Lessons deeper than `course/section/file` | 736 (12.3 %) |
| Sections merging several source folders | 64 of 681 |
| …of which folder-per-lesson, correct as-is | 49 |
| **…of which genuinely lost sections** | **13, holding 371 lessons** |
| Sections lost to a title collision instead | 3, holding 79 lessons |

Two independent causes, both fixed here.

**Nesting.** `run-scan.handler.ts` read `relSegments[0]` — the first folder
below the course — as the section for every lesson, so anything deeper was
folded into it. The clearest case is a six-week bass course:

```
pos 1  Slap_Bass_-_Week_1/00_-_Introduction.mkv
pos 2  Slap_Bass_-_Week_2/00_-_Introduction.mkv
pos 3  Slap_Bass_-_Week_3/00_-_Introduction.mkv
...
pos 7  Slap_Bass_-_Week_1/01_-_A_Brief_History_of_Slap_Bass.mkv
```

Six weeks in one section of 39 lessons, ordered by the file ordinal, so the
course opens with all six introductions back to back. The filenames parse
perfectly — no parser tier can fix this, because the information that was lost
is the folder boundary.

**Title collision.** Lessons found their section through `sectionIdByTitle`.
`27. Enemy AI` and `38. Enemy AI` both parse to the label "Enemy AI", so the
second folder's 25 lessons joined the first folder's section.

## The rule, and why it is not the path depth

A folder holding **exactly one** video is a lesson folder — the Udemy-style
layout where a lesson gets its own directory for slides and exercises. A
folder holding **several** videos is a section.

Splitting on depth instead would have produced 49 wrong splits in the same
library: a 31-lesson chess course, every lesson in its own folder as
`video.mp4`, would have become 31 sections of one lesson each. The rule never
climbs above the first folder below the course, so that layout imports exactly
as it does today.

Section order is the composed ordinals of the whole path, not of the deepest
segment: `06 Go на Практике/11 Как Писать Тесты` is `[6, 11]` and sorts before
`08 Работа с Docker` (`[8]`) where it belongs. Same reasoning
`lesson-position.ts` already applies to composite `N.M` filenames.

## Acceptance

- A course laid out `Course/Block/Week/video.mp4` shows one section per
  `Week`, not a single section named `Block`
- Lessons inside those sections run in the author's order
- A folder holding exactly one video stays a lesson: the 31-folder
  `[Фоксфорд] Шахматы` layout imports unchanged
- Two sibling folders reducing to the same title import as two sections
- A flat course is unchanged
- A rescan that moves a lesson into a new section keeps the lesson's id —
  LessonProgress, Bookmark, Note and Transcript reference `lessonId` with no
  foreign key behind them

## Spec diff

none — `SectionDto` and `SectionOutline` carry no path, and the section's
source folder stays a scan-internal detail.

## Codegen impact

no

## Schema impact

yes — `Section.sourcePath` (nullable TEXT) plus
`@@unique([courseId, sourcePath])`, migration
`20260921121500_section_source_path`. Nullable with no backfill: the value is
the folder a rescan resolves under the new rule, which needs the file tree and
cannot be derived in SQL. Existing rows keep NULL and match by title exactly
as before; the first force-resync of a course fills its sections in. Postgres
treats NULLs as distinct in a unique index, so those rows and every flat
course's synthetic "Lessons" section are exempt by construction.

## Design impact

no

## Tests

Handler tests per layout: nested subfolders become sections; a one-video
folder does not; two folders sharing a title stay two sections; a nested
section sorts by its composed path key; lessons inside run in author order.
Domain unit tests for `resolveSectionFolder` / `sectionSortKey` /
`compareSectionKeys`. Force-resync tests for the migration path: the folder is
recorded, a persisted id is matched by folder, two folders sharing a title
never claim one id, and a lesson moved into a new nested section keeps its id.

## Notes

- Opened from the measurement above, taken while evaluating whether a
  classifier model could help the scan. It cannot: every ordering defect found
  on the library is extraction or structure, not classification.
- Known ceiling: at depth 4+ a lesson folder resolves to the first segment
  rather than to its own parent — 5 lessons in the measured library. Splitting
  those needs a video count for a directory's whole subtree rather than for
  its immediate children.
- The change takes effect on a force-resync. An ordinary library-wide scan
  keeps sections exactly as persisted (#544), so nothing re-shapes itself
  under a user who did not ask for it.
