## Notes

- Completed: 2026-08-29
- Result: https://github.com/kkucherenkov/course_shelf/pull/194

Net: **-87 / +15** lines across the five workflow files.

**The acceptance line about caching was already satisfied before this card.**
`actions/setup-node` was already caching the pnpm store via `cache: pnpm`, and
`subosito/flutter-action`'s `cache: true` already implied the pub cache — it
gates that step on `pub-cache == '' && cache == 'true'`
([`action.yaml:132`](https://github.com/subosito/flutter-action/blob/v2/action.yaml)).
So this action does not add caching; `pub-cache: "true"` is stated explicitly
only to decouple it, so turning the SDK cache off later cannot silently take the
pub cache with it.

**What the card was actually worth** is the version drift it closes. The Node
version was written as a literal `"24"` in `quality.yml`, `e2e.yml` and both
`regen-snapshots.yml` jobs, and as `${{ env.NODE_VERSION }}` in `ci.yml` and
`release.yml`. Workflow `env` does not cross files, so there was no way to bump
Node once. `FLUTTER_VERSION` had the same shape and carries a load-bearing
constraint — it must match the version the goldens were rendered with — which
now sits on the input it governs instead of on an `env` block two files away.

**Deviation — "used by every other CI job".** Nine of the ten jobs use it.
`codeql.yml`'s `analyze` does not: CodeQL's own action builds the database from
source and needs no pnpm, Node or Flutter on the runner.

**Deviation — the action also installs.** All nine jobs ran
`pnpm install --frozen-lockfile` immediately after the preamble, so it is folded
in rather than exposed as an input that would never be set to `false`. Same
reasoning kept the input list to four: two booleans that are genuinely load-
bearing (`codegen-drift` needs both toolchains, `flutter` needs Flutter without
Node) and two version overrides for a future matrix.
