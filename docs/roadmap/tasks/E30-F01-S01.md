## Goal

Add a metadata source without rebuilding the backend.

## Acceptance

- A JSON definition carries `id`, a URL pattern, and rules mapping CSS selectors or JSON paths onto course fields
  (not YAML — see [the design doc](../../superpowers/specs/2026-09-13-declarative-scrapers-design.md), D1: no YAML
  parser is reachable from `apps/backend`, and `course-json.schema.ts` already establishes the
  hand-rolled, dependency-free precedent for a second hand-authored format)
- Definitions are loaded into the existing `ScraperRegistry` at startup and dispatch through the existing `canHandle` / `scrape` port
- Executed by the existing `HtmlMetadataExtractor` plus a new pure `RuleExtractor` — a definition is data, never code
- A malformed definition is reported and skipped; it never prevents startup

## Notes

- The port is already the right shape — `Scraper { id, supportedKinds, canHandle, scrape }` with `DefaultScraperRegistry`, plus a generic `json-ld` fallback and an HTML metadata extractor. The only thing missing is registration without a rebuild.
- Deliberately **not** runtime JS plugins: sandboxing, versioning and the blast radius of arbitrary code are a large price for a personal instance. Configuration instead of code.
