## Goal

Make cue text searchable without dragging raw SQL into application code.

## Acceptance

- Migration runs `CREATE EXTENSION IF NOT EXISTS pg_trgm` and a GIN index `USING gin (text gin_trgm_ops)` on `transcript_cue`
- Search stays on Prisma `contains` — the same operator the adapter already uses
- The adapter carries a `ponytail:` comment naming the ceiling (no stemming, no `ts_rank`) and the upgrade path

## Notes

- `tsvector` was considered and rejected: a generated column cannot pick its text-search configuration from a sibling `language` column, so it would need `Unsupported("tsvector")` in the schema and `$queryRaw` on both the read and the write path. Trigram costs one extension and one index, and substring matching is what “find where they said X” means.
