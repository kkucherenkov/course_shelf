## Notes

- Completed: 2026-07-29

Byte source exists (`/lessons/{id}/stream-url`, materials `/download-url`).

**Two Notes claims were wrong and are corrected here.**

1. **Range _is_ supported.** The original note said the spec does not contract
   `Range`/`Accept-Ranges` and asked for confirmation before committing to
   resumable. `apps/backend/src/modules/streaming/streaming.controller.ts:212-266`
   implements `200`, `206`, `multipart/byteranges`, `416`, `400`, and sets
   `Accept-Ranges: bytes`. Caveat: that route is exempt from OpenAPI validation
   (binary body, in the validator's `ignorePaths`), so Range is an
   _implementation_ contract only — nothing in CI would catch its removal. See
   the follow-up card below.
2. **The TTL figure was wrong.** The note said 5 minutes; the real default is
   **900 s / 15 minutes** (`STREAM_TOKEN_TTL_SECONDS`,
   `apps/backend/src/common/config/app-config.ts:197`). Token-refresh-on-resume
   is still required, just on a 15-minute clock — implemented by minting a fresh
   signed URL on every fetch rather than caching one.

Net-new client deps added: `cryptography`, `workmanager`, `connectivity_plus`,
`async`, plus `sqlite3` and `path_provider_platform_interface` as dev deps.

**Deviations from the card, all deliberate:**

- **Tests** — the card asked for `integration_test simulating a flaky network`.
  This host has no emulator and cannot build iOS (`flutter devices` → Linux
  desktop only), so an `integration_test` could be written but never run.
  Delivered instead as `bloc_test` plus unit tests over a scripted byte source
  and a mocked Dio adapter, all under plain `flutter test`. 107 tests added
  (265 → 372).
- **Materials are not covered.** `getMaterialStream` sends whole files with no
  Range support by design, so lesson video and materials need different download
  paths. This card is video only.
- **iOS uses `BGProcessingTaskRequest`, not `BGAppRefreshTask`.**
  `workmanager_apple`'s `registerOneOffTask` never reaches `BGTaskScheduler` on
  iOS — it takes a `UIApplication.beginBackgroundTask` extension of the current
  session and runs the callback immediately. `registerProcessingTask` is what
  submits to `BGTaskScheduler`, so iOS routes through that, with
  `BGTaskSchedulerPermittedIdentifiers` + `UIBackgroundModes: processing` in
  `ios/Runner/Info.plist` and a registration in `AppDelegate.swift`. **None of
  the iOS half can be compiled, run, or verified on this host** — it was written
  against the installed plugin's Swift source and reviewed twice by reading, not
  by executing.
