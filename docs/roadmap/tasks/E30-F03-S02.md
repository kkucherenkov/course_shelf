## Goal

Let an admin review proposed metadata as a queue — accept or reject each
proposal per field — instead of the proposals existing only in the database.

## Why this exists

E30-F03-S01 shipped the direct edit plus a single-course prefill and
deliberately excluded the queue. That leaves four operations with no consumer
in `apps/web`.

The queue is not a second way to do what the editor already does. It is the
only path that links a scraped course to **entities**:
`apply-identify-result.handler.ts:89-103` resolves the fragment's raw names
through `upsertInstructorsByName`, `upsertStudioByName` and `upsertTagsByName`,
creating the instructor / studio / tag rows as needed. The editor's
scrape-preview panel shows those same names as read-only hints precisely
because it cannot resolve them — its own card says so. So today the only way to
attach an instructor to a scraped course is to type the name into the entity
picker by hand, once per course.

It is also the only surface where a proposal survives the request that made it:
`scrapeCoursePreview` is synchronous and its candidate is gone when the panel
closes, while an `IdentifyTask` is a row with a status that an admin can leave
and come back to.

## Acceptance

- An admin-only queue surface listing identify tasks over `listIdentifyTasks`,
  with status, source, and the course each proposal targets
- A proposal opens into a per-field comparison: the course's current value next
  to the fragment's, one `MergeMode` control per field of `MergePolicyDto`
  (`title`, `description`, `level`, `language`, `posterUrl`, `releaseDate`,
  `ratingAverage`, `ratingCount`, `instructors`, `studios`, `tags`,
  `externalIds`)
- Apply sends the reviewed policy as `ApplyIdentifyRequest.mergePolicy`,
  overriding what the task stored; discard calls `discardIdentifyTask`
- The editor's scrape-preview panel gains a "queue for review" action over
  `runIdentifyTask`, so a candidate can become a task instead of only being
  applied field by field in place
- After an apply, the course's instructors / studios / tags reflect the
  resolved entities — the fragment's names are no longer a dead end
- A task already `applied` or `discarded` is read-only
- Non-admins never see the surface, and the guard is not merely visual
- Every string via `t()` in `en` and `ru`; `pnpm check:i18n` green

## Tests

Component specs: the queue renders a task per row; a per-field mode change is
carried into the `applyIdentifyResult` payload; discard calls the discard
operation and not apply; a completed task renders read-only; a non-admin does
not get the surface. Composable spec for the merge-policy payload construction.
