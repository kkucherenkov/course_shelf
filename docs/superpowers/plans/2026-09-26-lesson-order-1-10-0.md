# Lesson order — 1.10.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make lesson order correct and legible across the real library — new parser tiers where a filename or its folder carries an ordinal, a declarative human-authored override read as an input to ranking, and a per-lesson `orderSource` so a guessed order is visible as a guess.

**Architecture:** Positions stay what they already are — the 1-based rank a batch ranking function emits per section, never a stored sort key and never a row the scan must avoid overwriting. The change adds inputs to that ranking: a word-prefixed filename tier, a parent-folder ordinal tier, `mtime` as the last resort, and a new Postgres table `lesson_order_override` holding one ordered list of library-relative video paths per section. `assignLessonPositions` gains that list as a parameter and returns, per lesson, both the rank and which tier produced it. The admin route `PUT /api/v1/admin/courses/{id}/lesson-order` writes the override and immediately re-runs the same ranking function, so the screen the maintainer just dragged in reflows without waiting for a scan, using exactly the code path the scan uses.

**Tech Stack:** NestJS 11 + `@nestjs/cqrs`, Prisma + PostgreSQL 18, `express-openapi-validator` against the bundled OpenAPI spec, Vitest, Nuxt 4 SPA (`ssr: false`) with `@app/ui`, `@app/api-client-ts` (openapi-ts) and `@app/api-client-dart` (dart-dio) generated from `packages/specs`.

**Spec:** [`docs/specs/2026-09-26-whats-next-design.md`](../../specs/2026-09-26-whats-next-design.md) — locked decisions 5, 6, 7, 8, 9 and routine choices Q19, Q20, Q21, Q22. Read it before Task 1; every task below cites the decision it implements.

## Review Focus

Five conditions the spec implies that no task's headline behaviour exercises. Each has a test added to the task that owns the code; they are listed here once, together, because they are the ones most likely to bite the maintainer.

1. **A new file appears in a section whose override lists every old lesson.** The new lesson is unlisted, so it ranks behind every manual entry even when its filename says it is lesson 1. Expected: it lands last in the section with `orderSource` from its own heuristic tier, never `manual`, and never sharing a position. Test in Task 4.
2. **An override entry names a path whose lesson now lives in a different section** (a folder was renamed between scans). Expected: the entry stays in its old section's list and is skipped when ranking that section; the lesson ranks by heuristic in its new section. No crash, no duplicate position, the entry is not pruned (spec Q21). Test in Task 4 and Task 7.
3. **Two lessons in one section with no ordinal, no folder ordinal and the identical `mtime`.** Expected: the `videoPath` tiebreak decides, deterministically, and the two positions differ. This is the case today's comparator gets wrong — see Task 4's finding. Test in Task 4.
4. **`PUT .../lesson-order` names a lesson id belonging to a different course, or a section id belonging to a different course.** Expected: 422 `application/problem+json`, nothing written. This is the cross-course id-smuggling class that `#544` had to bolt a `courseId` check onto in the scan. Test in Task 8.
5. **`PUT .../lesson-order` names the same lesson twice in one section, or sends an empty `lessonIds` array.** Expected: the duplicate is a 422 (silently de-duplicating would put two lessons on one rank); the empty array clears that section's override and the section falls back to heuristics. Test in Task 8.

```ts
// /tmp/claude-1000/<session>/scratchpad/order-measure.ts
import { readFileSync } from 'node:fs';
import path from 'node:path';
import { parseFolderName, parseLessonFileName } from '../../../home/kkucherenkov/projects/petProjects/course_shelf/apps/backend/src/modules/catalog/domain/scan/folder-name.parser';

const WORD_PREFIXED_RE = /^(\p{L}+(?:\s+\p{L}+)*)\s+(\d+)(?:[\s\-._]+(.+))?$/u;

interface Row { slug: string; sectionId: string; sectionFolder: string; videoPath: string; mtime: string }

const rows: Row[] = readFileSync(process.argv[2]!, 'utf8')
  .split('\n')
  .filter((l) => l.trim() !== '')
  .map((l) => {
    const [slug, sectionId, sectionFolder, videoPath, mtime] = l.split('\t');
    return { slug: slug!, sectionId: sectionId!, sectionFolder: sectionFolder!, videoPath: videoPath!, mtime: mtime! };
  });

/** Course-relative segments: videoPath is library-relative, so drop the course folder. */
function relSegments(videoPath: string): string[] {
  return videoPath.split('/').slice(1);
}

function folderOrdinal(r: Row): number | undefined {
  const segs = relSegments(r.videoPath);
  if (segs.length < 2) return undefined;
  const ownDir = segs.slice(0, -1).join('/');
  if (ownDir === r.sectionFolder) return undefined; // same for every sibling — no signal
  return parseFolderName(segs.at(-2) ?? '').ordinal;
}

const tally = { parsed: 0, wordPrefixed: 0, folder: 0, mtimeOnly: 0 };
const mtimeOnlyRows: Row[] = [];

for (const r of rows) {
  const base = path.basename(r.videoPath);
  if (parseLessonFileName(base).ordinal !== undefined) { tally.parsed++; continue; }
  if (WORD_PREFIXED_RE.test(base.slice(0, base.lastIndexOf('.')))) { tally.wordPrefixed++; continue; }
  if (folderOrdinal(r) !== undefined) { tally.folder++; continue; }
  tally.mtimeOnly++;
  mtimeOnlyRows.push(r);
}

console.log('tier counts', tally, 'total', rows.length);

// Per-course spread for what only mtime can order.
const bySlug = new Map<string, Row[]>();
for (const r of mtimeOnlyRows) bySlug.set(r.slug, [...(bySlug.get(r.slug) ?? []), r]);
for (const [slug, rs] of [...bySlug].toSorted((a, b) => b[1].length - a[1].length).slice(0, 15)) {
  const times = rs.map((r) => Date.parse(r.mtime)).toSorted((a, b) => a - b);
  const spreadSeconds = (times.at(-1)! - times[0]!) / 1000;
  const distinct = new Set(times).size;
  console.log(
    slug.padEnd(48),
    String(rs.length).padStart(4),
    'distinct', String(distinct).padStart(4),
    'spread_s', String(Math.round(spreadSeconds)).padStart(9),
  );
}
```

- [ ] **Step 4: Check whether `mtime` agrees with a known-good order**

Spread alone is not signal — timestamps can be spread and still wrong. Where a course *does* carry parseable ordinals, `mtime` order can be checked against them. Append to the script and re-run:

```ts
// Agreement check: on lessons whose filename DOES parse an ordinal, does
// mtime order agree with ordinal order inside the same section?
let pairs = 0;
let agree = 0;
const bySection = new Map<string, Row[]>();
for (const r of rows) {
  const base = path.basename(r.videoPath);
  if (parseLessonFileName(base).ordinal === undefined) continue;
  bySection.set(r.sectionId, [...(bySection.get(r.sectionId) ?? []), r]);
}
for (const rs of bySection.values()) {
  const byOrdinal = rs.toSorted(
    (a, b) =>
      (parseLessonFileName(path.basename(a.videoPath)).ordinal ?? 0) -
      (parseLessonFileName(path.basename(b.videoPath)).ordinal ?? 0),
  );
  for (let i = 1; i < byOrdinal.length; i++) {
    pairs++;
    if (Date.parse(byOrdinal[i]!.mtime) >= Date.parse(byOrdinal[i - 1]!.mtime)) agree++;
  }
}
console.log('mtime agrees with filename ordinal on', agree, 'of', pairs, 'adjacent pairs',
  `(${((agree / pairs) * 100).toFixed(1)}%)`);
```

### Task 4: Ranking — override input, folder and mtime tiers, and `orderSource`

Spec decision 5 (parent folder, then `mtime`), decision 6 and 9 (the override is an input to ranking), decision 8 (an ordered list of paths; unlisted entries keep their heuristic key and rank behind), Q22 (`orderSource` per lesson).

**A finding this task must fix.** `lesson-position.ts`'s comparator is

```ts
const diff = sortKey(a.parsed) - sortKey(b.parsed);
if (diff !== 0) return diff;
return a.videoPath.localeCompare(b.videoPath);
```

and `sortKey` returns `Number.POSITIVE_INFINITY` when no ordinal parses. Two such entries give `Infinity - Infinity === NaN`, `NaN !== 0` is `true`, so the comparator returns `NaN` and the `videoPath` tiebreak is never reached. ECMA-262's `CompareArrayElements` coerces a `NaN` comparator result to `+0`, and `toSorted` is stable, so those entries keep their input order — which is `FsAdapter.walk()`'s enumeration order, the exact thing the file's WHY comment says is "not guaranteed stable across two directory listings on every filesystem". Verified:

```sh
node -e 'const e=[{p:"b"},{p:"a"}];const k=()=>Infinity;
console.log(JSON.stringify(e.toSorted((x,y)=>{const d=k(x)-k(y);if(d!==0)return d;return x.p.localeCompare(y.p);})))'
# → [{"p":"b"},{"p":"a"}]   — not sorted
```

So the 344 lessons the spec describes as "placed by path sort" are in fact placed by walk order. The new comparator never subtracts two sentinels.

```ts
/** Where a lesson's position came from. Mirrors the OpenAPI `LessonOrderSource`. */
export type OrderSource = 'parsed' | 'folder' | 'mtime' | 'manual';

export interface LessonPositionInput {
  readonly videoPath: string;
  readonly parsed: ParsedLessonFileName;
  /**
   * Ordinal of the folder the lesson sits in, when that folder is BELOW the
   * section folder. Absent when the lesson sits directly in its section — see
   * `lessonFolderOrdinal`.
   */
  readonly folderOrdinal?: number;
  /** File modification time. The last-resort key; see the WHY above. */
  readonly mtime: Date;
}

export interface LessonPlacement {
  readonly position: number;
  readonly orderSource: OrderSource;
}

/**
 * Ordinal of the lesson's own folder, when it has one below the section.
 *
 * Returns undefined when the lesson's directory IS the section folder: every
 * sibling would then read the same ordinal (the section's), which orders
 * nothing and would mislabel the placement as `folder`. The signal only
 * exists in the folder-per-lesson layout — `Course/Block/03 Урок/video.mp4` —
 * which `resolveSectionFolder` deliberately keeps as a lesson, not a section,
 * because a folder holding exactly one video is a lesson folder.
 *
 * `relSegments` is course-relative and includes the filename, matching
 * `courseRelativeSegments` in `run-scan.handler.ts`. `sectionFolder` is the
 * course-relative folder `resolveSectionFolder` returned, i.e. the value
 * stored in `Section.sourcePath`.
 */
export function lessonFolderOrdinal(
  relSegments: readonly string[],
  sectionFolder: string | undefined,
): number | undefined {
  if (relSegments.length < 2) return undefined;
  const ownDir = relSegments.slice(0, -1).join('/');
  if (ownDir === (sectionFolder ?? '')) return undefined;
  return parseFolderName(relSegments.at(-2) ?? '').ordinal;
}

/**
 * The composed parsed key, or undefined when the filename carried no ordinal.
 * Undefined rather than a sentinel: subtracting two `Infinity` sentinels
 * produces `NaN`, which ECMA-262 coerces to `+0` inside a sort comparator, so
 * the next tiebreak never runs and the entries keep their input (walk) order.
 */
function parsedKey(parsed: ParsedLessonFileName): number | undefined {
  if (parsed.sectionOrdinal !== undefined && parsed.ordinal !== undefined) {
    return parsed.sectionOrdinal * 1_000_000 + parsed.ordinal;
  }
  return parsed.ordinal;
}

/** Ascending; `undefined` sorts last. Never subtracts two sentinels. */
function compareOptional(a: number | undefined, b: number | undefined): number {
  if (a === b) return 0;
  if (a === undefined) return 1;
  if (b === undefined) return -1;
  return a < b ? -1 : 1;
}

function compareHeuristic(a: LessonPositionInput, b: LessonPositionInput): number {
  const byParsed = compareOptional(parsedKey(a.parsed), parsedKey(b.parsed));
  if (byParsed !== 0) return byParsed;

  const byFolder = compareOptional(a.folderOrdinal, b.folderOrdinal);
  if (byFolder !== 0) return byFolder;

  const byMtime = a.mtime.getTime() - b.mtime.getTime();
  if (byMtime !== 0) return byMtime;

  return a.videoPath.localeCompare(b.videoPath);
}

function heuristicSource(entry: LessonPositionInput): Exclude<OrderSource, 'manual'> {
  if (parsedKey(entry.parsed) !== undefined) return 'parsed';
  if (entry.folderOrdinal !== undefined) return 'folder';
  return 'mtime';
}

/**
 * Assigns 1-based positions to every entry, scoped to a single section.
 * Callers must group entries by sectionId before calling this.
 *
 * `override` is the human-declared order for this section: an ordered list of
 * library-relative video paths. Entries it names rank first, in list order,
 * as `manual`. Everything else ranks behind them by the heuristic chain. An
 * override path with no entry behind it is skipped here and kept in storage —
 * the caller never prunes it, so a file restored after a rename regains its
 * place (spec Q21).
 */
export function assignLessonPositions(
  entries: readonly LessonPositionInput[],
  override: readonly string[] = [],
): Map<string, LessonPlacement> {
  const declaredIndex = new Map<string, number>();
  for (const [index, videoPath] of override.entries()) {
    if (!declaredIndex.has(videoPath)) declaredIndex.set(videoPath, index);
  }

  const listed: LessonPositionInput[] = [];
  const unlisted: LessonPositionInput[] = [];
  for (const entry of entries) {
    (declaredIndex.has(entry.videoPath) ? listed : unlisted).push(entry);
  }

  const ordered = [
    ...listed.toSorted(
      (a, b) => (declaredIndex.get(a.videoPath) ?? 0) - (declaredIndex.get(b.videoPath) ?? 0),
    ),
    ...unlisted.toSorted(compareHeuristic),
  ];

  const placements = new Map<string, LessonPlacement>();
  for (const [index, entry] of ordered.entries()) {
    placements.set(entry.videoPath, {
      position: index + 1,
      orderSource: declaredIndex.has(entry.videoPath) ? 'manual' : heuristicSource(entry),
    });
  }
  return placements;
}
```

### Task 5: Schema — the enum, `Lesson.orderSource`, and the override table

Spec decision 9: the override lives in Postgres, because the derived volume is keyed by `libraryId` (a cuid, so a rebuilt database orphans everything under the old one) and is not backed up — the only backup is `pg_dump` (`admin/infra/pg-dump-archiver.ts`).

**Shape decision, and why.** One row per section, holding the order as a `text[]`. The alternative — one row per entry with a `position` column — reintroduces exactly the renumbering the spec rejected in decision 8: inserting a lesson rewrites every row after it. An array column is rewritten whole on every save, which is what "declare the order" means, and a section holds tens of entries, not thousands.

**Key decision, and why.** `(courseId, sectionSourcePath)`, not `(courseId, sectionId)`. A force-resync re-derives sections from disk and only reuses a section id when its `sourcePath` matches (`run-scan.handler.ts:905-935`) — so `sourcePath` is the durable key and the id is not. The flat-course synthetic "Lessons" section has no folder, so it is stored as `''` rather than `NULL`: Postgres treats `NULL`s as distinct in a unique index, and a nullable key would let one course hold two override rows for its flat section.

It is not: `run-scan.handler.ts` builds it from `courseRelativeSegments(courseFolder, …)`, so it is **course-relative**. The `videoPaths` in the new table are library-relative, matching `Lesson.videoPath`. Fix the stale comment in the same pass.

- [ ] **Step 2: Write the adapter**

```ts
/**
 * WHY this file exists:
 * Prisma adapter for LessonOrderOverrideRepository — the only place in the
 * Catalog context that knows the `lesson_order_override` table.
 *
 * `videoPaths` is a Postgres text[]: the order IS the array, so a save is one
 * row rewritten rather than N rows renumbered. That is the whole point of
 * spec decision 8 — a map of path→position rewrites itself every time a
 * lesson is inserted.
 */
import { Injectable } from '@nestjs/common';

import { PrismaService } from '../../../common/prisma/prisma.service';

import type {
  LessonOrderOverrideMap,
  LessonOrderOverrideRepository,
} from '../domain/lesson/lesson-order-override.repository';

@Injectable()
export class PrismaLessonOrderOverrideRepository implements LessonOrderOverrideRepository {
  constructor(private readonly prisma: PrismaService) {}

  async findByCourse(courseId: string): Promise<LessonOrderOverrideMap> {
    const rows = await this.prisma.lessonOrderOverride.findMany({
      where: { courseId },
      select: { sectionSourcePath: true, videoPaths: true },
    });
    return new Map(rows.map((r) => [r.sectionSourcePath, r.videoPaths]));
  }

  async findByCourses(
    courseIds: readonly string[],
  ): Promise<ReadonlyMap<string, LessonOrderOverrideMap>> {
    if (courseIds.length === 0) return new Map();
    const rows = await this.prisma.lessonOrderOverride.findMany({
      where: { courseId: { in: [...courseIds] } },
      select: { courseId: true, sectionSourcePath: true, videoPaths: true },
    });
    const byCourse = new Map<string, Map<string, readonly string[]>>();
    for (const row of rows) {
      const bucket = byCourse.get(row.courseId) ?? new Map<string, readonly string[]>();
      bucket.set(row.sectionSourcePath, row.videoPaths);
      byCourse.set(row.courseId, bucket);
    }
    return byCourse;
  }

  async replaceForSections(
    courseId: string,
    sections: ReadonlyMap<string, readonly string[]>,
  ): Promise<void> {
    if (sections.size === 0) return;
    const empty = [...sections].filter(([, paths]) => paths.length === 0).map(([key]) => key);
    const filled = [...sections].filter(([, paths]) => paths.length > 0);

    await this.prisma.$transaction(async (tx) => {
      if (empty.length > 0) {
        await tx.lessonOrderOverride.deleteMany({
          where: { courseId, sectionSourcePath: { in: empty } },
        });
      }
      for (const [sectionSourcePath, videoPaths] of filled) {
        await tx.lessonOrderOverride.upsert({
          where: {
            uq_lesson_order_override_course_section: { courseId, sectionSourcePath },
          },
          create: { courseId, sectionSourcePath, videoPaths: [...videoPaths] },
          update: { videoPaths: [...videoPaths] },
        });
      }
    });
  }
}
```

The per-section loop inside the transaction is not the N+1 the handbook bans: the row count is the number of sections the admin actually reordered, bounded by one course's sections, and each write is a distinct key that `createMany` cannot express as an upsert.

- [ ] **Step 2: Write `lesson-order-merge.ts`**

```ts
/**
 * WHY this file exists:
 * Merging a newly declared section order with the entries already stored for
 * it. Spec 2026-09-26 Q21 keeps an entry whose path no lesson currently has,
 * rather than pruning it, so a file restored after a rename or a re-import
 * "regains its place". Regaining a PLACE, not a slot at the end, is why this
 * anchors each kept entry after the entry that preceded it in storage instead
 * of appending — an appended entry means the admin reorders the section twice
 * for one restored file.
 *
 * The caller decides what counts as unmatched: `declared` is the full new
 * order for paths that DO have lessons, so anything in `stored` outside it is
 * either an entry with no lesson (keep) or a lesson the admin dropped from
 * the list (also outside `declared`, also kept — it simply ranks behind, by
 * its heuristic key, which is the half-ordered-section rule of decision 8).
 */

/**
 * @param stored   the section's order as persisted, oldest declaration
 * @param declared the order the admin just sent, paths only
 * @returns the order to persist: `declared`, with every `stored` entry it
 *          omits re-inserted immediately after its nearest surviving
 *          predecessor (or at the head when it had none).
 */
export function mergeDeclaredOrder(
  stored: readonly string[],
  declared: readonly string[],
): string[] {
  const declaredSet = new Set(declared);

  /** kept path → the declared path it must follow, or undefined for the head. */
  const anchors: { path: string; after: string | undefined }[] = [];
  let lastSurviving: string | undefined;
  for (const path of stored) {
    if (declaredSet.has(path)) {
      lastSurviving = path;
      continue;
    }
    anchors.push({ path, after: lastSurviving });
  }

  const merged: string[] = [];
  const headKeepers = anchors.filter((a) => a.after === undefined).map((a) => a.path);
  merged.push(...headKeepers);

  for (const path of declared) {
    merged.push(path);
    for (const anchor of anchors) {
      if (anchor.after === path) merged.push(anchor.path);
    }
  }

  // A kept entry anchored to a path the admin did not re-send has no slot in
  // the loop above; it goes last rather than being dropped.
  for (const anchor of anchors) {
    if (!merged.includes(anchor.path)) merged.push(anchor.path);
  }

  return merged;
}
```

```ts
/**
 * WHY this file exists:
 * Aggregate → LessonOrderDto. This is the ONE place a library-relative video
 * path leaves the backend, and it does so only as `unmatched`, only on an
 * admin-guarded route, and only because the spec's Risks section requires the
 * screen to show entries the record holds that no lesson matches — otherwise
 * "the record becomes a place where wrongness accumulates unseen". Matched
 * lessons travel as ids and titles; NFR-S-01 holds for them as everywhere.
 */
import type { LessonOrderOverrideMap } from './domain/lesson/lesson-order-override.repository';
import type { Course } from './domain/course/course';
import type { Lesson } from './domain/lesson/lesson';
import type { LessonOrderDto } from '@app/api-client-ts';

export function toLessonOrderDto(
  course: Course,
  lessons: readonly Lesson[],
  override: LessonOrderOverrideMap,
): LessonOrderDto {
  const bySection = new Map<string, Lesson[]>();
  for (const lesson of lessons) {
    bySection.set(lesson.sectionId, [...(bySection.get(lesson.sectionId) ?? []), lesson]);
  }
  const knownPaths = new Set(lessons.map((l) => l.videoPath));

  return {
    courseId: course.id,
    sections: course.sections.map((section) => {
      const sectionKey = section.sourcePath ?? '';
      return {
        sectionId: section.id,
        title: section.title,
        position: section.position,
        lessons: (bySection.get(section.id) ?? [])
          .toSorted((a, b) => a.position - b.position)
          .map((lesson) => ({
            lessonId: lesson.id,
            title: lesson.title,
            position: lesson.position,
            ...(lesson.orderSource === undefined ? {} : { orderSource: lesson.orderSource }),
          })),
        unmatched: (override.get(sectionKey) ?? []).filter((p) => !knownPaths.has(p)),
      };
    }),
  };
}
```

```ts
import { Inject } from '@nestjs/common';
import { IQueryHandler, QueryHandler } from '@nestjs/cqrs';

import { COURSE_REPOSITORY } from '../../domain/course/course.repository';
import { CourseNotFoundError } from '../../domain/course/course.errors';
import { LESSON_REPOSITORY } from '../../domain/lesson/lesson.repository';

import type { CourseRepository } from '../../domain/course/course.repository';
import type { LessonRepository } from '../../domain/lesson/lesson.repository';
import type { LessonOrderOverrideRepository } from '../../domain/lesson/lesson-order-override.repository';
import type { LessonOrderDto } from '@app/api-client-ts';

@QueryHandler(GetCourseLessonOrderQuery)
export class GetCourseLessonOrderHandler
  implements IQueryHandler<GetCourseLessonOrderQuery, LessonOrderDto>
{
  constructor(
    @Inject(COURSE_REPOSITORY) private readonly courseRepo: CourseRepository,
    @Inject(LESSON_REPOSITORY) private readonly lessonRepo: LessonRepository,
    @Inject(LESSON_ORDER_OVERRIDE_REPOSITORY)
    private readonly overrideRepo: LessonOrderOverrideRepository,
  ) {}

  async execute(query: GetCourseLessonOrderQuery): Promise<LessonOrderDto> {
    const course = await this.courseRepo.findById(query.courseId);
    if (!course) throw new CourseNotFoundError(query.courseId);

    const [lessons, override] = await Promise.all([
      this.lessonRepo.findByCourse(query.courseId),
      this.overrideRepo.findByCourse(query.courseId),
    ]);

    return toLessonOrderDto(course, lessons, override);
  }
}
```

```ts
/**
 * WHY this file exists:
 * Writes a human-declared lesson order and immediately re-runs the SAME
 * ranking the scan runs, so the screen the admin just dragged in reflows
 * without waiting for a rescan.
 *
 * Re-ranking here is not "patching positions". `assignLessonPositions` is
 * called with the new override as an input and emits 1..N ranks exactly as it
 * does inside the scan — no row is marked untouchable and no flag is stored
 * (spec 2026-09-26, decisions 6 and 9). Running the scan's own function is
 * also what keeps the two paths from drifting: a rescan five minutes later
 * must produce the identical order.
 *
 * Returns void. The controller chains GetCourseLessonOrderQuery for the
 * response body (handbook → CQRS, command return type rule).
 */
import { Inject } from '@nestjs/common';
import { CommandHandler, ICommandHandler } from '@nestjs/cqrs';
import path from 'node:path';

import { COURSE_REPOSITORY } from '../../domain/course/course.repository';
import { CourseNotFoundError } from '../../domain/course/course.errors';
import { LESSON_REPOSITORY } from '../../domain/lesson/lesson.repository';
import { LESSON_ORDER_OVERRIDE_REPOSITORY } from '../../domain/lesson/lesson-order-override.repository';
import {
  LessonOrderDuplicateLessonError,
  LessonOrderLessonUnknownError,
  LessonOrderSectionUnknownError,
} from '../../domain/lesson/lesson-order.errors';
import { mergeDeclaredOrder } from '../../domain/lesson/lesson-order-merge';
import { parseLessonFileName } from '../../domain/scan/folder-name.parser';
import { assignLessonPositions, lessonFolderOrdinal } from '../../domain/scan/lesson-position';

import { SetCourseLessonOrderCommand } from './set-course-lesson-order.command';

import type { CourseRepository } from '../../domain/course/course.repository';
import type { LessonRepository } from '../../domain/lesson/lesson.repository';
import type { LessonOrderOverrideRepository } from '../../domain/lesson/lesson-order-override.repository';

@CommandHandler(SetCourseLessonOrderCommand)
export class SetCourseLessonOrderHandler
  implements ICommandHandler<SetCourseLessonOrderCommand, void>
{
  constructor(
    @Inject(COURSE_REPOSITORY) private readonly courseRepo: CourseRepository,
    @Inject(LESSON_REPOSITORY) private readonly lessonRepo: LessonRepository,
    @Inject(LESSON_ORDER_OVERRIDE_REPOSITORY)
    private readonly overrideRepo: LessonOrderOverrideRepository,
  ) {}

  async execute(command: SetCourseLessonOrderCommand): Promise<void> {
    const course = await this.courseRepo.findById(command.courseId);
    if (!course) throw new CourseNotFoundError(command.courseId);

    const lessons = await this.lessonRepo.findByCourse(command.courseId);
    const lessonById = new Map(lessons.map((l) => [String(l.id), l]));
    const sectionById = new Map(course.sections.map((s) => [s.id, s]));

    // ---- Validate everything before writing anything. -------------------
    const declaredBySectionKey = new Map<string, string[]>();
    for (const declared of command.sections) {
      const section = sectionById.get(declared.sectionId);
      if (!section) {
        throw new LessonOrderSectionUnknownError(declared.sectionId, command.courseId);
      }
      const seen = new Set<string>();
      const paths: string[] = [];
      for (const lessonId of declared.lessonIds) {
        if (seen.has(lessonId)) {
          throw new LessonOrderDuplicateLessonError(lessonId, declared.sectionId);
        }
        seen.add(lessonId);
        const lesson = lessonById.get(lessonId);
        // The sectionId check is also the cross-course check: `lessons` came
        // from this course, so a lesson of another course is simply absent.
        if (!lesson || lesson.sectionId !== declared.sectionId) {
          throw new LessonOrderLessonUnknownError(lessonId, declared.sectionId);
        }
        paths.push(lesson.videoPath);
      }
      declaredBySectionKey.set(section.sourcePath ?? '', paths);
    }

    // ---- Merge with what is stored, keeping unmatched entries. ----------
    const stored = await this.overrideRepo.findByCourse(command.courseId);
    const toStore = new Map<string, string[]>();
    for (const [sectionKey, declaredPaths] of declaredBySectionKey) {
      toStore.set(sectionKey, mergeDeclaredOrder(stored.get(sectionKey) ?? [], declaredPaths));
    }
    await this.overrideRepo.replaceForSections(command.courseId, toStore);

    // ---- Re-rank with the scan's own function. --------------------------
    const effective = new Map<string, readonly string[]>(stored);
    for (const [sectionKey, paths] of toStore) effective.set(sectionKey, paths);

    await this.lessonRepo.parkPositionsForResync(command.courseId);

    for (const section of course.sections) {
      const sectionLessons = lessons.filter((l) => l.sectionId === section.id);
      if (sectionLessons.length === 0) continue;
      const sectionKey = section.sourcePath ?? '';

      const placements = assignLessonPositions(
        sectionLessons.map((lesson) => {
          // videoPath is library-relative; the course folder is its first
          // segment, so course-relative segments are the rest.
          const relSegments = lesson.videoPath.split('/').slice(1);
          const folderOrdinal = lessonFolderOrdinal(relSegments, section.sourcePath);
          return {
            videoPath: lesson.videoPath,
            parsed: parseLessonFileName(path.basename(lesson.videoPath)),
            mtime: lesson.mtime,
            ...(folderOrdinal === undefined ? {} : { folderOrdinal }),
          };
        }),
        effective.get(sectionKey) ?? [],
      );

      for (const lesson of sectionLessons) {
        const placement = placements.get(lesson.videoPath);
        if (!placement) continue;
        await this.lessonRepo.save(
          lesson.withPlacement(placement.position, placement.orderSource),
        );
      }
    }
  }
}
```

```ts
/**
 * WHY this file exists:
 * Admin-only HTTP entry point for a course's declared lesson order
 * (E32-F01-S07). Composition only — dispatch, chain, return. Domain errors
 * become RFC 9457 through the global filter; `express-openapi-validator`
 * checks both directions against the bundled spec.
 *
 *   GET /api/v1/admin/courses/{id}/lesson-order → the current order
 *   PUT /api/v1/admin/courses/{id}/lesson-order → declare it, whole-course
 *
 * The PUT chains the query for its body because a command may not return a
 * DTO (handbook → CQRS, command return type rule).
 */
import { Body, Controller, Get, HttpCode, Param, Put, UseGuards } from '@nestjs/common';
import { CommandBus, QueryBus } from '@nestjs/cqrs';

import { AdminGuard } from '../../common/auth/admin.guard';
import { SetCourseLessonOrderCommand } from './application/commands/set-course-lesson-order.command';
import { GetCourseLessonOrderQuery } from './application/queries/get-course-lesson-order.query';

import type { LessonOrderDto, LessonOrderRequest } from '@app/api-client-ts';

@UseGuards(AdminGuard)
@Controller({ path: 'admin', version: '1' })
export class LessonOrderAdminController {
  constructor(
    private readonly commandBus: CommandBus,
    private readonly queryBus: QueryBus,
  ) {}

  /** GET /api/v1/admin/courses/:id/lesson-order */
  @Get('courses/:id/lesson-order')
  async getLessonOrder(@Param('id') id: string): Promise<LessonOrderDto> {
    return this.queryBus.execute<GetCourseLessonOrderQuery, LessonOrderDto>(
      new GetCourseLessonOrderQuery(id),
    );
  }

  /** PUT /api/v1/admin/courses/:id/lesson-order */
  @Put('courses/:id/lesson-order')
  @HttpCode(200)
  async setLessonOrder(
    @Param('id') id: string,
    @Body() body: LessonOrderRequest,
  ): Promise<LessonOrderDto> {
    await this.commandBus.execute<SetCourseLessonOrderCommand, void>(
      new SetCourseLessonOrderCommand(id, body.sections),
    );
    return this.queryBus.execute<GetCourseLessonOrderQuery, LessonOrderDto>(
      new GetCourseLessonOrderQuery(id),
    );
  }
}
```

```ts
/**
 * Course lesson-order composable (E32-F01-S07).
 *
 * Wraps `getCourseLessonOrder` and `setCourseLessonOrder` for the reorder
 * block on `pages/courses/[id]/edit.vue`. The server always answers with the
 * order it computed, so `save` replaces local state with the response rather
 * than trusting the local array — a lesson the admin left out of a section
 * ranks behind the listed ones by its heuristic key, and that reflow is
 * something only the server knows.
 *
 * The `useAsyncData` handler is memoised per courseId, matching
 * `useCourseEdit` — Nuxt warns on a changing handler identity otherwise.
 */
import { computed, ref, type Ref } from 'vue';
import { client, getCourseLessonOrder, setCourseLessonOrder } from '@app/api-client-ts';
import type { LessonOrderDto, LessonOrderSectionDto, Problem } from '@app/api-client-ts';

export type LessonOrderStatus = 'idle' | 'pending' | 'success' | 'error';

const handlerCache = new Map<string, () => Promise<LessonOrderDto>>();

function handlerFor(courseId: string): () => Promise<LessonOrderDto> {
  let cached = handlerCache.get(courseId);
  if (!cached) {
    cached = async () => {
      const res = await getCourseLessonOrder({ client, throwOnError: false, path: { id: courseId } });
      if (res.error) {
        const p = res.error as Problem;
        throw new Error(p.detail ?? p.title ?? 'Request failed');
      }
      return res.data as LessonOrderDto;
    };
    handlerCache.set(courseId, cached);
  }
  return cached;
}

export interface UseCourseLessonOrderReturn {
  sections: Ref<LessonOrderSectionDto[]>;
  status: Ref<LessonOrderStatus>;
  error: Ref<Error | null>;
  refetch: () => Promise<void>;
  saving: Ref<boolean>;
  hasChanges: Ref<boolean>;
  /** Move one lesson within one section. Out-of-range indices are ignored. */
  move: (sectionIndex: number, from: number, to: number) => void;
  reset: () => void;
  save: () => Promise<Error | null>;
}

export function useCourseLessonOrder(courseId: string): UseCourseLessonOrderReturn {
  const saving = ref(false);
  const sections = ref<LessonOrderSectionDto[]>([]);
  const baseline = ref<string>('[]');

  const { data, status, error, refresh } = useAsyncData<LessonOrderDto>(
    `course-lesson-order:${courseId}`,
    handlerFor(courseId),
    { lazy: true },
  );

  function adopt(dto: LessonOrderDto): void {
    sections.value = dto.sections.map((s) => ({ ...s, lessons: [...s.lessons] }));
    baseline.value = JSON.stringify(idsOf(sections.value));
  }

  watch(data, (value) => {
    if (value) adopt(value);
  });

  function idsOf(list: LessonOrderSectionDto[]): string[][] {
    return list.map((s) => s.lessons.map((l) => l.lessonId));
  }

  const hasChanges = computed(() => JSON.stringify(idsOf(sections.value)) !== baseline.value);

  function move(sectionIndex: number, from: number, to: number): void {
    const section = sections.value[sectionIndex];
    if (!section) return;
    if (from === to) return;
    if (from < 0 || to < 0 || from >= section.lessons.length || to >= section.lessons.length) return;
    const lessons = [...section.lessons];
    const [moved] = lessons.splice(from, 1);
    if (!moved) return;
    lessons.splice(to, 0, moved);
    sections.value[sectionIndex] = { ...section, lessons };
  }

  function reset(): void {
    if (data.value) adopt(data.value);
  }

  async function save(): Promise<Error | null> {
    saving.value = true;
    try {
      const res = await setCourseLessonOrder({
        client,
        throwOnError: false,
        path: { id: courseId },
        body: {
          sections: sections.value.map((s) => ({
            sectionId: s.sectionId,
            lessonIds: s.lessons.map((l) => l.lessonId),
          })),
        },
      });
      if (res.error) {
        const p = res.error as Problem;
        return new Error(p.detail ?? p.title ?? 'Request failed');
      }
      data.value = res.data as LessonOrderDto;
      adopt(res.data as LessonOrderDto);
      return null;
    } finally {
      saving.value = false;
    }
  }

  return {
    sections,
    status: status as Ref<LessonOrderStatus>,
    error: error as Ref<Error | null>,
    refetch: async () => {
      await refresh();
    },
    saving,
    hasChanges,
    move,
    reset,
    save,
  };
}
```

## What this plan does not do

Three tracks run in parallel per the spec's Q13, as refined by Q16. This plan is the **order lane** only.

- **The debt reconciliation pass** — 46 tuxedo items checked against the code, stale ones closed, survivors carded (spec decisions 4 and Q3, Q10). Q16 puts it in the **coordinator session, not a worktree**, because lanes may not write tuxedo and that is its entire job. Nothing in this plan touches tuxedo except Task 11's closing note, which the coordinator may prefer to make itself.
- **The mobile revival and its audit rig** — an Android emulator against a seeded local stack driven by `integration_test`, built *before* the device pass so the pass produces a score rather than a feeling (spec decision 2, Q5, Q12, Q15, Q18). Q16 has that lane **waiting for the Docker stack**, which this lane holds for its duration: the subnet is pinned at `docker/compose.yml:10`, so only one stack can run. The spec's own risk says "three parallel tracks is really two" — do not start the mobile lane while this one is running.
- **`orderSource` in the mobile UI.** Task 2 puts it on `LessonDto`, so the regenerated Dart client carries it; nothing in `apps/mobile` reads it. That belongs to the mobile lane.
- **`orderSource` on `LessonOutlineItem`.** The course detail page does not show it — only the admin editor does. Widening the public outline is a separate decision about what a learner should see, and the spec does not make it.
- **Concurrency on the reorder write.** Spec Open threads: Q21 settled staleness against the scan and explicitly set aside the two-tabs case as thin on a one-person instance. A version token and a 409 is the correct answer the day there is a second admin, and this plan does not build it.
- **Portability of the order.** Q17 rejected the derived-file export (option D) rather than dismissing it. If moving course folders between instances becomes a real workflow, the export is the thing to add.
- **A fifth `orderSource` value.** The spec flags the four as a taxonomy that "will want a fifth the moment another tier is added, and widening a published enum is the expensive kind of change". This plan ships exactly four and adds no extension mechanism.
