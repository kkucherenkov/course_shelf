## Tests

46 new unit tests across four specs; full backend suite green at 1598 passed /
2 skipped. The ones that matter are the refusals:

- a token signed under the **streaming** HKDF info is rejected here — the
  property that makes a second signer safe rather than a second key leak
- `locate()` rejects `../../etc/passwd` and `/etc/passwd` **without touching the
  filesystem**
- a client/server major mismatch throws before `pg_dump` is invoked at all
- a failed or timed-out dump deletes its partial file
- the download route refuses a missing/empty token without consulting the signer
  or the disk, and rejects a bad token *before* locating the archive, so error
  shape does not leak which ids exist

## Notes

- Completed: 2026-08-29
- Result: https://github.com/kkucherenkov/course_shelf/pull/196

**The acceptance line's "sqlite copy" is dead.** There is no SQLite backend —
see [ADR-0008](../../adr/0008-postgres-only.md) and the cancelled
[E23-F01-S02](./E23-F01-S02.md). `pg_dump --format=custom` is the only path, and
it produces **one** artefact carrying schema and data together, restored with
`pg_restore`, so the card's "Prisma schema + data dump" does not need two files.

**Decisions taken with the user before coding**, both recorded because either
could reasonably have gone the other way:

1. `pg_dump` binary in the image (`postgresql18-client`, major pinned) rather
   than a hand-rolled SQL dumper. The alternative needed maintaining alongside
   every migration and would not restore with `pg_restore`.
2. A separate `BackupTokenSigner` rather than a third scope on
   `StreamTokenSigner` (wrong bounded context) or a generic extraction
   (refactoring a live security path for one caller).

**Why the download route is not behind `AdminGuard`.** A browser attaches no
`Authorization` header to a plain `<a href download>`, and the web client keeps
its bearer token in localStorage. Possession of the link is therefore possession
of the archive — bounded by a 5-minute default TTL, an unguessable id, and a
token bound to that one id. This is the same trade the lesson and material
streaming routes already make, not a new one.

**Deviation — no UI.** No backup surface exists in the design bundle or in any
web card, so this is API-only. Nothing consumes `createBackup` yet.

**Deviation — course media is not backed up.** Only the metadata database. Files
under `COURSES_PATH` are the operator's; a restore against missing files
degrades to missing lessons, not a corrupt install. Stated in the endpoint
description because it is easy to assume otherwise.

**Not verified locally: the image build.** Docker is unavailable in this
environment, so `apk add postgresql18-client` was never executed. The package's
presence in alpine 3.23/3.24 `main` (18.6-r0 — the two bases `node:24-alpine`
uses) was confirmed from the Alpine package index, not from a build. CI builds
this image in the e2e job.
