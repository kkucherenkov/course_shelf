## 1 — Roadmap bookkeeping

### 1.1 `docs/roadmap/README.md` reports 115 stories; there are 121

`docs/roadmap/README.md:3`, `:14`, `:23` all say **115**. The directory holds
121 card files, and `docs/roadmap/TODO.md:11` correctly says
`118 / 119 complete — 121 cards, 2 cancelled`.

`README.md` is generated by `tools/generate.py`; the six cards added after the
last regeneration (`E13-F02-S09/S10`, `E17-F01-S11..S14` and friends) never
made it back into the header. Either rerun the generator or hand-fix three
numbers — but the two documents currently disagree in the same directory.

### 1.2 `ROADMAP.md` Gantt marks all 108 non-critical stories `:active`

```
grep -oE ':(active|done|crit),' docs/roadmap/ROADMAP.md | sort | uniq -c
 108 :active,
   7 :crit,
```

Zero `:done`. 118 of these stories have shipped. The diagram renders the
project as if nothing has landed since April.

This one has no cheap fix — a Gantt that needs 118 hand-edited status tokens
will drift again the day after it is corrected. **Recommendation: delete the
Gantt** and keep `TODO.md` as the single progress view, or teach
`generate.py` to emit `:done` from each card's Status field. The current
middle ground is worse than either.

### 1.3 `specs/tasks/active.md` still lists work that shipped

```
_Remaining follow-up (not carded): per-lesson download state + tap-to-download
once **E19** `DownloadsBloc` lands (#101)._
```

That work landed in PR #198 (`specs/tasks/done.md`, entry `T-2026-08-29-006`) —
`apps/mobile/lib/features/course_detail/presentation/course_detail_screen.dart:27`
now carries both the per-lesson tap-to-enqueue and the course-level CTA, and
issue #101 is closed. The note should be deleted.

### 1.4 GitHub issue mirroring covers 46 of 121 cards

`.claude/CLAUDE.md` states: *"Every roadmap card in `docs/roadmap/tasks/` is
mirrored as GitHub issues."* Counting distinct `[<card-id>]` title prefixes
across all 154 issues yields **46** unique ids — E15 through E24 plus stragglers.
E00–E14 (roughly 80 cards) were never mirrored.

This is a rule that describes an intention, not the repository. Either backfill
80 issues or narrow the rule to *"cards from E15 onward"*. Leaving it as-is
means the next agent to read CLAUDE.md will search for issues that do not exist
and draw wrong conclusions about what is tracked.

## 6 — Root README: four false claims

`README.md` and `README.ru.md` are the front door. Each currently misstates a
guarantee.

1. **`README.md:70`** — *"Four locales (en, ru, uk, el) are wired across all
   three apps with a key-parity check that runs in CI."* Three errors in one
   sentence: web ships **2** locales (`apps/web/i18n/locales/{en,ru}.ts`),
   backend ships **1** (`apps/backend/src/i18n/en/`), and the parity check
   runs in no workflow. Only mobile has four.
2. **`README.md:119`** — *"test with coverage enforcement."*
   `apps/backend/vitest.config.ts:16-19` configures the v8 provider and two
   reporters. There are no thresholds. Nothing enforces coverage.
3. **`README.md:124` / `README.ru.md:124`** — *"Security: `pnpm audit`."*
   The job runs **osv-scanner v2.3.8** in Docker with a jq severity gate
   (`ci.yml`, *Dependency vulnerability scan*). `pnpm audit` is not invoked.
   The real implementation is better than the claim; the claim is just wrong.
4. **Flutter 3.41 → 3.44.** Six occurrences per README
   (`:26, :70, :88, :137, :227, :287`), twelve across both files.
   `apps/mobile/pubspec.yaml:8` requires `>=3.44.0` and
   `.github/actions/setup-cs/action.yml:35` pins `3.44.4`.

`docs/troubleshooting.md:190` compounds #4: it tells the reader to point
`.fvmrc` at `3.41.0`. There is no `.fvmrc` in `apps/mobile`, and 3.41.0 is
below the pubspec floor — following that instruction breaks the build.

## 7 — Spec coverage: four binary routes live outside `paths`

`packages/specs/openapi/openapi.yaml` documents 57 path items.
`apps/backend/src/common/openapi/openapi-validator.middleware.ts:86` exempts
four route families from validation:

```
/v1/stream/lessons/
/v1/stream/materials/
/v1/admin/backups/<id>/download
/v1/auth/        (Better Auth owns its protocol — legitimately out of scope)
```

The first three exist as `@Get` handlers in `streaming.controller.ts:182,297,385`
and `admin-backup.controller.ts` but have no OpenAPI path item. They are
described in prose in the spec (`openapi.yaml:3411,3484`) and the exemption
carries a written rationale — binary bodies, no JSON schema to validate.

The rationale is defensible but not complete: OpenAPI 3.1 expresses
`application/octet-stream` and `video/mp4` responses fine, and adding the path
items would give the generated clients typed methods and let the validator
check *parameters* even where it cannot check the body. As it stands, the
`.claude/CLAUDE.md` rule *"never introduce an HTTP route without updating
openapi.yaml"* has four standing exceptions that a reader of the rule would
not expect.

Also open: 4 Redocly `no-required-schema-properties-undefined` warnings in
`ScrapePreviewRequest` (`openapi.yaml:5155,5160,5165`).

## 8 — Hard-coded English in the design system

Both catalogs ship user-visible strings that no locale can reach.

| Location | String |
| --- | --- |
| `packages/ui_flutter/lib/src/progress/app_progress_badge.dart:281` | `Text('Done')` |
| `packages/ui_flutter/lib/src/progress/app_progress_badge.dart:289` | `Text('Locked')` |
| `packages/ui_flutter/lib/src/progress/app_spinner.dart:34` | `semanticLabel = 'Loading'` |
| `packages/ui/src/components/AppNoteEditor/AppNoteEditor.vue:186` | `'Failed — retrying'` |
| `packages/ui/src/components/AppNoteEditor/AppNoteEditor.vue:187` | `'Offline — queued'` |

`AppNoteEditor.vue:25` (`placeholder`) is a default prop and is overridable —
acceptable. The five above are computed or positional and are not.

This violates *"never ship a user-visible string without `t()` /
`AppLocalizations`"* in `.claude/CLAUDE.md`. The fix is an override prop per
string, not a `t()` call inside a design-system package — `@app/ui` and
`ui_flutter` must stay locale-agnostic.
