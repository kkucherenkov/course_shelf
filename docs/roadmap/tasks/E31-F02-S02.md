## Goal

Three controls sit in Settings and do nothing. On a single-owner instance, account deletion is meaningless and the other two are cosmetic.

## Acceptance

- Avatar upload, email change and account deletion removed from the Settings UI
- No dead handlers or unused API calls left behind
- The Known-limits row is removed from `docs/user-guide.md`

## Notes

- A control that looks operable and is not is worse than an absent one: it costs the owner a support conversation with themselves.
- All three were `disabled` buttons with no handler, so there was nothing dead
  to unwire and no orphaned API call. The backend never grew an avatar-upload,
  email-change or account-deletion route, so no endpoint was orphaned either.
- The avatar row went whole: without its upload/remove buttons it was a
  control row with no control. The email row stays — reading your own address
  is useful — minus the dead **Change** button, with the truthful
  `profileEmailHelp` string in place of `profileEmailComingSoon`.
- Eleven now-dead keys dropped from both web locales (`pnpm check:i18n` green).
- The page had no spec before; `apps/web/app/pages/__tests__/settings.spec.ts`
  is new. It asserts the three controls are absent, asserts the surviving ones
  are present so a broken mount cannot pass vacuously, and asserts the page
  ships no `button[disabled]` at all.
