## Notes

- Completed: 2026-08-29
- Result: (PR pending)

**Deviation — storage source.** The sub-step said "storage usage from
`path_provider` + Drift sums". Drift sums do give CourseShelf's own usage, but
`path_provider` returns *paths*, not capacity, and Dart exposes no free-space
API at all. The device half needs a platform call, so `disk_space_plus` was
added (decision taken with the user before implementing). It reports megabytes —
undocumented on pub.dev, confirmed from the package's own example — and the
conversion to bytes lives in exactly one place. The adapter never throws: a
storage bar is decoration, and the bar degrades to CourseShelf's own figure
when the platform declines to answer.

**Scope taken on — the queue had no entry point.** `EnqueueLesson` /
`EnqueueCourse` were dispatched from nowhere in the app, so the tab could only
ever have been empty outside tests. #101 (E18-F01-S03's remaining sub-step) is
therefore included here: per-lesson tap-to-download and the course-level CTA on
course detail, both live. Decided with the user rather than shipping a tab
nothing could fill.

**Blocker found and worked around — there is no local catalog.**
`AppDownloadRow` needs a lesson and a course name. `cached_lessons` /
`cached_courses` exist but **nothing populates them** — `CachedCatalogDao` has
no callers anywhere in the app — and the Downloads tab is an offline surface
that must not fetch. So `downloaded_lessons` gained `lesson_title` /
`course_title` (schema v2 -> v3), written at enqueue time from course detail,
which has both in hand. That is also the more correct answer once a cache does
exist: a download outlives the catalog entry it came from, and an unpublished
course or a cleared cache would otherwise leave a file the UI cannot name. Rows
predating v3 fall back to the lesson id, deliberately ugly rather than blank.

**Deviation — tests.** The card asks for `integration_test`. Same constraint
E19-F01-S01 recorded: no emulator on this host and no iOS build, so it could be
written but never run. Covered instead by widget tests over seeded state and
`blocTest` over the real bloc. The split is deliberate — a bloc's event
processing is microtask-driven and does not reliably progress inside the widget
tester's fake-async zone, so mixing the two made tests pass on frame counts
rather than on behaviour.

**Not verified on a device.** `disk_space_plus` has native code on both
platforms and was never executed here — the same "written against the plugin
and reviewed by reading" caveat E19-F01-S01 carries for its iOS half.
