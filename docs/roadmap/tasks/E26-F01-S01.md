## Goal

Fix a defect that has been shipped since E14: **subtitles have never worked on the web.** `useLessonPlayer` toggles `videoEl.textTracks`, but the lesson page renders no `<track>`, so the list is always empty and the player's subtitle button does nothing.

## Acceptance

- One `<track>` per `LessonDto.subtitles[]` entry, `kind="subtitles"`, with `srclang` and `label` from the DTO
- The track matching the UI locale carries `default`
- `src` derived from the already-signed stream URL via a pure `buildSubtitleUrl(streamUrl, language)`
- Malformed input yields no `<track>` rather than `src="undefined"`
- The subtitle button in the player chrome visibly works

## Spec diff

none — `LessonDto.subtitles[]` and the route have existed since E06/E08

## Tests

Unit spec for `buildSubtitleUrl`: path segment, token preservation, encoding, port and prefix, and non-URL input. Plus a manual check against a lesson with a real sidecar.

## Sub-steps

## Notes

- The subtitle route was documented from the start as *“Same token as the video endpoint — a `<track>` element cannot send an Authorization header either”*. It was designed for this element and then never wired up.
