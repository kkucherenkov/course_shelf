## Goal

Let an admin correct a course's metadata by hand, and optionally pre-fill the
form from a source, instead of being limited to whatever a scraper could reach.

## Why this exists

Measured 2026-09-13: `apps/web` contains **zero** references to `updateCourse`,
`scrapeCoursePreview` or `identifyTask`. The server side is complete —
`PATCH /courses/{id}` accepts 14 fields, and a whole identify pipeline
(`scrapeCoursePreview` → `runIdentifyTask` → `listIdentifyTasks` →
`applyIdentifyResult` / `discardIdentifyTask`, with a per-field merge policy)
sits behind no UI at all. The pipeline was built; the surface never was.

This is also the only thing that makes an unreachable source workable. Udemy's
course pages are behind a Cloudflare JS challenge and its Affiliate API has been
closed to new access since 2025-01-01, so no scraper will ever read them — but
the admin already has the page open in a logged-in browser. A form is the
difference between "cannot be catalogued" and "takes a minute".

It is also the genre's normal shape: in comparable library managers a scraper
**pre-fills a form**, it does not replace one. A human stays the last step
because every source is eventually wrong or silent.

## Acceptance

- An admin-only edit surface for a course, reachable from
  `apps/web/app/pages/courses/[id].vue`
- Covers every field `UpdateCourseRequest` accepts: `title`, `description`,
  `slug`, `instructorIds`, `studioIds`, `tagIds`, `level`, `language`,
  `releaseDate`, `posterUrl`, `ratingAverage`, `ratingCount`, `externalIds`,
  `sourceUpdatedAt`
- Entity fields (`instructorIds`, `studioIds`, `tagIds`) pick from existing
  entities rather than asking for raw ids
- A **"fill from source"** action over `scrapeCoursePreview`: takes a URL or a
  name, shows the candidate's fields next to the current ones, and applies
  **per field** — never a blanket overwrite
- A field left untouched is not sent; the form never rewrites a value the admin
  did not look at
- Non-admins never see the surface, and the guard is not merely visual
- Every string via `t()` in `en` and `ru`; `pnpm check:i18n` green

## Notes

- Opened from `tuxedo` 93 after finding the gap while looking for a way to
  catalogue Udemy courses.
- The identify **queue** (`listIdentifyTasks` / `applyIdentifyResult` /
  `discardIdentifyTask`) is deliberately **not** in this card. It is a second
  surface with its own review flow; this one is the direct edit plus a
  single-course prefill. Splitting keeps the valuable half shippable.
- `tuxedo` 94 tracks a separate defect found in passing: the `updateCourse`
  description in `openapi.yaml` still claims it takes only title / description /
  slug. Whoever builds this will notice; the fix belongs to that task, not here.
- The scrape-preview panel applies `title`, `description`, `level`, `language`,
  `releaseDate`, `posterUrl`, `ratingAverage`+`ratingCount` (paired), and
  `externalIds` per field. `instructorNames`/`studioName`/`tags` are shown as
  read-only hints — the fragment carries raw names, not entity ids, and
  resolving them is Stage 4 (the identify pipeline), which this card
  deliberately excludes.
- Entity multi-select composes Nuxt UI's `USelectMenu` (`multiple`,
  `ignore-filter`, server-side search) directly rather than a new `@app/ui`
  primitive — no existing primitive covers async multi-select, and Nuxt UI
  already ships one; wrapping it added no brand logic worth a component.
